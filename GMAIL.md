# Gmail integration

The deployed `aivora-gmail` Edge Function implements Google OAuth and owner-scoped Gmail operations. `gmail.js` adds a Gmail workspace to the existing site. Gmail account consent and real mailbox/send verification are still required from the user; deploying this code does not grant mailbox access. Phone and WhatsApp integration remain pending.

Configuration: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and a random 32-byte base64 `GMAIL_TOKEN_KEY` are stored in Supabase Secrets, never source. Callback is `https://pdvovstitmkjkmgqfjwi.supabase.co/functions/v1/aivora-gmail/oauth/callback`. The Google project currently uses external test mode; the intended user was added as a test user. Google verification and long-lived consent requirements must be addressed before opening to other customers. Do not publish Google's OAuth app merely to bypass testing restrictions.

OAuth uses random one-time state hashes, 10-minute expiry and S256 PKCE. Callbacks consume state with a single database DELETE RETURNING, so a replay cannot reconnect an account. Google access and refresh tokens are AES-GCM encrypted with random IVs before storage. Integration tables have RLS enabled and all privileges revoked from anon/authenticated; only the server role can read them. Browser API routes validate the Supabase user with Auth on every request, enforce owner filters and restrict CORS to https://aivora.tr. `verify_jwt=false` permits the Google callback; it does not bypass application endpoint authentication.

Scopes are gmail.readonly and gmail.send. Inbox fetches the latest ten messages. Plain text is rendered with textContent; attachments, remote images and HTML are not rendered. Mailbox content is not sent to the AI. Preparing a send stores an immutable sender/recipient/subject/body review; sending requires a separate explicit confirmation and atomically claims the pending review. Expired or previously used confirmations cannot send. Network ambiguity is reported without automatic retry. Disconnect attempts Google revocation and removes Aivora connection, OAuth state and send review records; Gmail messages are untouched. Stored send reviews are retained until disconnect. Hourly prepare limit is 30 per user; this is application throttling, not a Google billing guarantee.

Validation: `node gmail-tests.mjs` checks auth, CORS, encryption, PKCE parameters, rejected callback state, token non-disclosure, header injection, explicit approval, owner isolation and single-use send. Existing `node edge-tests.mjs` covers previous features. Database privilege/RLS checks verify server-only access. Local UI fixtures use fake tokens and stubbed Gmail data and are not published. No real mail is sent during automated validation.

Limitations: no Gmail AI reply drafting, attachments, mailbox search/pagination, background polling, push notifications or autonomous sending in this iteration. Existing content draft management is independent; Gmail sending uses its own review UI. Google OAuth remains the user's final authorization step.
